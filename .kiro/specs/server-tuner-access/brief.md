# チューナーサーバー連携機能

## この機能が提供するもの

EPGStation ServerがMirakurunまたはmirakcへ接続し、放送局、番組、チューナー、ロゴ、および放送ストリームを利用できるように
する機能である。

Mirakurun専用のクライアントパッケージには依存せず、両製品が公開する共通のREST APIとストリームAPIを直接利用する。最低対応
版はMirakurun 3.8.0、mirakc 3.1.10とし、それ以降を対応範囲とする。

番組情報の更新、予約のチューナー割当、録画、ライブ視聴、放送局ロゴの取得に対し、接続先製品が異なっても同じ業務上の結果を
提供する。

## 主な機能

### 接続先の準備

-   サーバー設定から接続先を取得する
-   ネットワーク上のHTTP接続、同じ機器内のUnixドメインソケット、Windowsの名前付きパイプを利用する
-   番組情報、予約、録画、ライブ視聴が同じ接続設定を利用できるようにする
-   接続先専用の認証情報、通信代理、TLS証明書の設定は提供しない

共通の情報照会、ロゴ取得、変更取得、ストリーム取得は、公開されたREST APIとストリームAPIを利用する。mirakc固有の拡張は、
それを必要とする処理だけが利用する。

### 情報の取得

-   チューナーサーバーの稼働状態と版情報を取得する
-   利用可能なチューナーと対応する放送波を取得する
-   放送局の一覧を取得する
-   番組の一覧と個別番組を取得する
-   放送局ロゴを取得する
-   Mirakurunとmirakcの表現差をEPGStationの利用側へ持ち込まず、同じ業務結果として返す

取得した情報の保存、番組表への変換、予約へのチューナー割当は、それぞれの利用機能が担当する。

### 番組・放送局の変更取得

-   Mirakurunの番組・放送局変更ストリームを継続して受け取る
-   mirakcの更新通知と、必要な放送局別番組取得を利用する
-   一部の通信エラーや通知内容の解析失敗を番組情報管理へ伝える
-   Mirakurunの変更ストリームが通常の終了または切断を返した場合も取得処理を終了するが、通信エラーや解析失敗と同じ切断通
    知は番組情報管理へ伝えない

通知の集約、保存、再接続、全件同期は番組情報・番組表機能が担当する。通知の順序、重複、欠落を検出する共通の連番は提供しな
い。

### 録画用ストリーム

-   番組を指定して録画用ストリームを取得する
-   時刻指定予約では放送局を指定して録画用ストリームを取得する
-   予約管理が選んだ取得優先度を接続先へ数値として伝える
-   録画の中止または終了時にEPGStation側のストリーム接続を破棄できるようにする

### ライブ視聴用ストリーム

-   放送局を指定してライブ視聴用ストリームを取得する
-   映像配信が選んだ取得優先度を接続先へ数値として伝える
-   視聴終了または配信異常時にEPGStation側のストリーム接続を破棄できるようにする

複数の録画と視聴が競合したときの受理、拒否、入替は接続先が決定する。EPGStation側の接続を破棄した後、接続先でチューナー資
源の解放が完了したことを確認する共通の応答は持たない。

### 応答時間と再試行

-   起動時の稼働状態確認を除き、稼働状態、放送局、番組、チューナー、ロゴなどの一回のREST照会には、操作ごとに設定する有限
    な応答時間を適用する
-   録画またはライブ視聴では、HTTP応答を受け取ってストリームを利用側へ引き渡すまでに限って有限な応答時間を適用する
-   変更通知、録画ストリーム、ライブ視聴ストリームの継続時間そのものには一律の終了時間を設けない
-   個別照会に失敗した場合は利用側へエラーを返し、この機能が一律に自動再試行しない

## 起動時の接続確認

1. サーバー設定から接続先を準備する。
2. チューナーサーバーの稼働状態を問い合わせる。
3. 問い合わせに失敗した場合は1秒待って再試行する。
4. 成功するまで、予約、録画、Web UI・APIなどの後続機能を開始しない。

起動時の接続確認は、長時間稼働するサービスの依存回復処理である。一回ごとの稼働状態確認にも、総試行回数または総待機時間に
もEPGStation独自の上限を追加しない。

## 放送局ロゴを取得する流れ

1. 番組情報・番組表が対象放送局を指定する。
2. 保存済み情報がロゴなしを示す場合は、ロゴが存在しない結果を返す。
3. ロゴありの場合は接続先へ画像を要求する。
4. 取得できた場合は画像を返し、取得に失敗した場合はロゴなしとは異なるエラーを返す。
5. 画像はEPGStationへ保存せず、照会のたびに接続先から取得する。

## 異常時の動作

-   起動時に接続できない場合は、1秒間隔で稼働状態の確認を続ける
-   起動後の一回のREST照会、またはストリームを利用側へ引き渡すまでの確立処理が応答時間を超えた場合は、その要求を失敗とし
    て利用側へ返す
-   個別の情報取得に失敗した場合は、再試行せず依頼元へエラーを返す
-   変更取得の接続が終了、切断、またはエラーになった場合は、番組情報・番組表機能が再接続を試みる。ただしMirakurunの通常
    の終了と切断は、通信エラーや解析失敗と同じ切断通知を発生させない
-   ストリーム取得に失敗した場合は、録画または映像配信へエラーを返す
-   取得中のストリームが終了またはエラーになった場合は利用側へ伝え、途切れた位置から自動再開しない

## 他の機能との関係

### 利用する機能

-   サーバー設定管理機能（`server-configuration`）: 接続先、取得優先度、および操作ごとの応答時間を提供する。
-   運用ログ記録機能（`server-operational-logging`）: 接続確認、情報取得、変更取得、およびストリーム取得の異常を記録す
    る。

### この機能を利用する機能

-   サーバー起動・稼働管理機能（`server-application-runtime`）: 起動時にチューナーサーバーへ接続できるまで待機する。
-   映像配信・再生連携機能（`server-media-delivery`）: 放送局のストリームをライブ視聴に利用する。
-   番組情報・番組表機能（`server-program-guide`）: 放送局、番組、変更通知、およびロゴを取得する。
-   予約録画実行機能（`server-recording-execution`）: 番組または放送局のストリームを録画に利用する。
-   録画予約管理機能（`server-reservation-management`）: 競合計画に用いるチューナー情報を取得する。

## この機能に含めないもの

-   番組情報の保存、検索、削除
-   予約競合の計算とチューナー割当の判断
-   録画時刻、録画再試行、録画状態の管理
-   放送ストリームの変換、HLS配信、視聴セッションの管理
-   Mirakurunまたはmirakc自体の起動、設定、監視、再起動
-   HTTPS、接続先専用の認証、通信代理、証明書設定
