# 番組情報・番組表機能

## この機能が提供するもの

チューナーサーバーから放送局と番組の情報を取得してEPGStationへ保存し、番組表、番組詳細、放送中番組、番組検索、放送局ロゴ
を利用できるようにする機能である。

開始時に放送局と番組をまとめて取得し、その後は変更通知を継続的に反映する。予約、自動予約ルール、録画、IPTV番組表も同じ保
存済み情報を利用する。

Mirakurunとmirakcのどちらを利用する場合も、同じ放送局・番組・ロゴの業務結果を利用側へ提供する。

## 主な機能

### 放送局情報の管理

-   視聴可能な放送局の識別子、名称、放送波、チャンネル番号、リモコン番号、サービス識別子、ロゴの有無などを保存する
-   設定で除外された放送局や放送サービスを番組表の対象から外す
-   放送局の追加と変更を受け取り、保存済み情報へ反映する
-   放送局の削除通知だけでは、保存済みの放送局と関連番組を直ちに削除しない

### 番組情報の更新

-   開始時と再接続時に、対象となる放送局と番組をまとめて取得する
-   番組の追加、変更、削除を受け取り、同じ番組に対する連続した変更を保存前にまとめる
-   放送中または放送開始が近い番組を短い間隔で保存する
-   それ以外の番組は設定された更新間隔を基準に保存する
-   番組リレーや同時放送の関連情報を、保存する中心番組の選択に利用する
-   放送終了時刻を過ぎた番組を定期的に削除する

変更通知には、切断をまたいだ再開位置、重複、欠落を検出する共通の連番を保持しない。通知接続を再開した場合は、放送局と番組
の全件同期を一度試みる。

### 保存する番組情報

-   番組識別子、放送局、開始・終了時刻、番組名、説明、詳細説明、無料・有料を保存する
-   番組名へ設定に応じた囲み文字の置換を適用し、半角化した番組名から括弧表記を除いた短縮表示名を作る（[前]・[後]は位置に関わらず末尾へ残し、前編と後編を区別する）
-   ジャンルは先頭から最大3件を保存する
-   映像情報は一組を保存する
-   音声情報は主音声として扱う一組を保存する
-   番組リレーや同時放送の関連情報そのものは保存せず、保存対象となる中心番組の選択に利用する
-   通常表記に加え、表示と検索に利用する半角表記を保持する

### 番組表と番組詳細

-   放送波、放送局、期間、無料番組のみといった条件で番組表を取得できる
-   期間の開始時点または終了時点に重なる番組も対象に含める
-   番組を指定し、番組名、説明、詳細情報、最大3件のジャンル、映像情報、主音声情報などを取得できる
-   指定した番組が存在しない場合は、見つからない結果を返す

### 放送中番組と番組検索

-   各放送局で放送中の番組を取得できる
-   キーワード、除外キーワード、放送局、放送波、ジャンル、曜日、時間帯、無料・有料、番組の長さなどの条件で検索できる
-   通常キーワードは選択された項目ごとに照合し、指定された条件を組み合わせて絞り込む
-   正規表現検索を利用できない場合は、通常キーワード検索として処理する
-   放送局識別子と放送波の両方を指定した場合は、放送局識別子を優先する
-   検索結果は開始時刻順で返し、同じ開始時刻の番組どうしの順序は定めない
-   検索件数の指定がある場合は、その件数まで返す

### 放送局ロゴ

-   保存済み放送局にロゴがあるかを確認する
-   ロゴがある放送局について、照会のたびにチューナーサーバーから画像を取得する
-   放送局が存在しない場合と、ロゴがない場合は見つからない結果として扱う
-   ロゴありの放送局から画像を取得できなかった場合は、取得失敗として扱う

## 番組情報更新の流れ

1. 対象となる放送局を取得し、除外設定を反映する。
2. 番組をまとめて取得し、保存対象となる中心番組を保存する。
3. 放送局と番組の変更通知を継続的に受け取る。
4. 放送中・放送間近の番組を優先しながら、受け取った変更を保存する。
5. 更新間隔ごとに、番組情報の更新を関係する機能へ知らせる。
6. 放送終了時刻を過ぎた番組を定期的に削除する。

全件取得と変更取得の経路によって、更新通知を出す時点は異なる。更新通知は、その時点までに保存された情報を利用できることを
知らせるが、すべての後続保存や関連処理の完了を一律には保証しない。

## 異常時の動作

-   放送局または番組の全件取得に失敗した場合は更新完了を知らせず、次の更新機会を待つ
-   変更通知の接続がエラーまたは切断状態になった場合は、待ち時間を増やしながら再接続を続ける
-   Mirakurunの変更ストリームが通常の終了または切断で終わった場合も再接続するが、通信エラーまたは解析失敗と同じ切断状態
    には切り替えない
-   通知接続を再開した場合は全件同期を一度試み、失敗しても通知受信を開始する
-   受信済み番組変更の保存に失敗した場合は、その回に取り出した変更を次の保存対象へ戻す
-   更新に失敗している間も、保存済み番組の読取と終了済み番組の定期削除を続ける
-   保存済み情報には鮮度による利用停止期限を設けない

## 他の機能との関係

### 利用する機能

-   サーバー設定管理機能（`server-configuration`）: 更新間隔と取得対象から除外する放送局やサービスを提供する。
-   運用ログ記録機能（`server-operational-logging`）: 放送局と番組の取得、更新、および検索の状況や失敗を記録する。
-   データベース保存・検索機能（`server-persistence`）: 放送局と番組を保存し、番組表と検索に必要な情報を提供する。
-   チューナーサーバー連携機能（`server-tuner-access`）: 放送局、番組、変更通知、およびロゴ画像を提供する。

### この機能を利用する機能

-   サーバー起動・稼働管理機能（`server-application-runtime`）: 起動時に番組情報の準備と更新を開始する。
-   状態変化通知・外部連携機能（`server-event-and-hook-delivery`）: 番組情報の更新を画面や外部処理へ通知する。
-   IPTV向けチャンネル一覧・番組表出力機能（`server-iptv-export`）: 保存された放送局と番組をチャンネル一覧と電子番組表に
    利用する。
-   予約録画実行機能（`server-recording-execution`）: 録画対象の番組と番組リレー先を確認する。
-   録画予約管理機能（`server-reservation-management`）: 番組を予約へ反映し、番組情報の変更へ追従する。
-   自動予約ルール機能（`server-reservation-rules`）: 検索条件に一致する番組を予約候補として探す。
-   Web・API・リアルタイム通知提供機能（`server-service-interface`）: 番組表、検索結果、番組詳細、放送中番組、およびロゴ
    を公開する。
-   機能間連携機能（`server-workflow-coordination`）: 番組情報の更新後に録画履歴の整理と予約の再計算を開始する。

## この機能に含めないもの

-   番組検索条件から自動予約を作る判断
-   予約競合の計算と録画開始の判断
-   番組表画面の配置、操作、表示方法
-   チューナーサーバーへの接続方式と通信処理
-   Web APIの経路、応答形式、認証
-   放送局と番組の保存方式や検索アルゴリズムの実装詳細
