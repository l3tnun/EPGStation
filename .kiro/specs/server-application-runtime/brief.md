# サーバー起動・稼働管理機能

## この機能が提供するもの

EPGStation Server 全体を起動し、録画予約、録画、番組情報更新、Web UI、API などを利用できる状態にする機能である。

設定とログを準備し、チューナーサーバーとデータベースが利用可能になるまで待ってから、予約・録画、保存先監視、Web
UI・API、起動時整理、番組情報更新を決められた順序で開始する。Web UI・API と番組情報更新の処理が停止した場合や起動エラー
になった場合は再起動を試みる。

## 対応実行環境

-   Node.js 24 系を最低対応版とする
-   Node.js 24 系で依存関係の導入、構築、起動、サーバーテストが成功することを確認する
-   Node.js 26 系も対応版として追加検証する
-   Node.js 24 系未満は対応環境として扱わない

## 主な機能

### 起動準備

-   運用ログを初期化する
-   サーバー設定を読み込む
-   必要に応じて、設定された OS ユーザーとグループで動作するように切り替える
-   実行主体を切り替えた後、予約・録画を管理する処理用のログ設定を読み込む
-   チューナーサーバーとデータベースが利用可能になるまで待機する

チューナーサーバーまたはデータベースへ接続できない場合は、確認処理が失敗を返した後に1秒待って再確認する。一回ごとの確認
にも依存先復旧待ち全体にもEPGStation独自の時間制限を追加せず、接続できるまで後続機能を開始しない。

### 予約・録画機能の準備

-   利用可能なチューナー情報を取得する
-   予約の競合判定と録画で使用するチューナー情報を設定する
-   予約、録画、録画済み番組、ルール、サムネイル、エンコードなどの状態変化を連携させる処理を開始する
-   録画保存先の空き容量監視を開始する

### Web UI・API の開始

-   Web UI、REST API、ファイル配信、リアルタイム通知を提供する別の処理を開始する
-   管理側とのプロセス間通信を設定する
-   Web UI・API の処理が終了または起動エラーになった場合は、同じ処理の再起動を試みる

### 起動時の状態整理

-   前回の終了時に録画中のまま残った録画情報を整理する
-   一時保存先に残った録画ファイルを通常の保存先へ移せる場合は移動を試みる
-   対応する予約を確認できた録画ファイルのサイズ情報を更新する
-   終了時刻を過ぎた予約を削除する
-   整理した状態変化を関係する機能へ通知する

Web UI・API の受付開始と、この状態整理の完了は同期しない。状態整理中に利用者からの要求を受け付ける場合がある。

### 番組情報更新の開始

-   チューナーサーバーから番組情報を取得・更新する処理を開始する
-   番組情報の更新完了を、予約更新などの関係する機能へ通知する
-   番組情報更新の処理が終了、切断、または起動エラーになった場合は、再起動を試みる

Web UI・API の受付開始、起動時の状態整理、番組情報更新の開始、最初の番組情報更新完了は別々に進む。サーバー全体の準備完了
を一つの状態として公開する機能は持たない。

### server テストの共通基盤と coverage の計測の道具

-   全サーバー機能が利用する共通テスト基盤を一度だけ所有する
-   単体テスト（仕様・実装）だけで server の `src/**` の C0・C1 を計測する道具を所有する

### 公開用 Docker image

-   Debian 版・Alpine 版の image を製品の Dockerfile から構築し、起動した server が Web・API に応答することを手元で確認する
-   公開用の image を GitHub Actions で構築して Docker Hub へ公開する（x86_64 以外の architecture を含む）

## 起動の流れ

1. 運用ログ、設定、必要な実行主体を準備する。
2. チューナーサーバーとデータベースが利用可能になるまで待つ。
3. チューナー情報、状態変化の連携、保存先監視を準備する。
4. Web UI・API・リアルタイム通知の提供を開始する。
5. 中断された録画情報と期限切れ予約を整理する。
6. 番組情報更新を開始する。

起動準備で失敗した場合は後続機能を開始せず異常終了する。Web UI・API や番組情報更新の処理が停止した場合は再起動を試みる。

## 他の機能との関係

### 利用する機能

-   サーバー設定管理機能（`server-configuration`）: 起動に必要な設定を提供する。
-   運用ログ記録機能（`server-operational-logging`）: 起動、停止、再起動、および異常を記録する。
-   チューナーサーバー連携機能（`server-tuner-access`）: 起動前の接続確認を提供する。
-   データベース保存・検索機能（`server-persistence`）: 起動前の接続確認と管理情報を提供する。
-   サーバー内部のプロセス間通信機能（`server-process-messaging`）: 別々に動く処理の通信相手を登録する。
-   機能間連携機能（`server-workflow-coordination`）: 起動時整理と機能間の後続処理を提供する。
-   録画予約管理機能（`server-reservation-management`）: 起動時の予約準備を提供する。
-   予約録画実行機能（`server-recording-execution`）: 録画待ちの構成と起動時整理を提供する。
-   録画済み番組管理機能（`server-recorded-content`）: 録画済み情報と実ファイルの起動時整理を提供する。
-   録画保存先の容量管理機能（`server-storage-management`）: 容量監視の開始を提供する。
-   Web・API・リアルタイム通知提供機能（`server-service-interface`）: 外部向け受付を提供する。
-   番組情報・番組表機能（`server-program-guide`）: 番組情報更新を提供する。

### この機能を利用する機能

-   なし

## この機能に含めないもの

-   予約の作成、競合判定、変更方法
-   録画開始時刻の判定と録画処理
-   番組情報の取得・更新方法
-   Web UI や各 API が提供する個別操作
-   データベースの保存方法
-   チューナーサーバーとの通信方法
