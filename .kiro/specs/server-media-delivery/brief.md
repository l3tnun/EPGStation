# 映像配信・再生連携機能

## この機能が提供するもの

放送中のチャンネルと録画ファイルを、ブラウザーや外部プレーヤーで視聴できるようにする機能である。

ライブ放送はM2TS、低遅延M2TS、WebM、MP4、HLSで配信できる。録画ファイルは直接再生・ダウンロードするほか、WebM、MP4、HLSへ
視聴中だけ変換して配信できる。配信中の一覧、HLSの準備状態と継続、個別停止、全停止も提供する。

## 主な機能

### ライブ放送の配信

-   チャンネル、配信形式、画質を指定してライブ視聴を開始する
-   変換方法を指定しないM2TSでは受信した放送データをそのまま配信する
-   低遅延M2TS、WebM、MP4、HLSでは、設定された方法で視聴中だけ変換して配信する
-   変換が必要な場合は、再生用のメディア変換実行枠を取得する
-   放送データの取得要求または変換の開始要求が配信受付前に失敗として返された場合は、配信開始を失敗とする
-   ライブM2TSを外部アプリで開くためのプレイリストを提供する

### 録画ファイルの再生とダウンロード

-   登録済みの録画ファイルを直接再生またはダウンロードする
-   録画元ファイルと変換済みファイルに応じて、設定された再生方法を選ぶ
-   WebM、MP4、HLSへ視聴中だけ変換して配信する
-   指定された再生位置から配信を開始する
-   録画中のファイルでは、ファイル末尾へ到達してから1秒後に大きさを確認し、増えていれば追記分を配信する
-   1秒後に大きさが変わっていなければ、録画状態が続いていても配信を終了する
-   ファイルが読取位置より小さくなった場合は先頭から読み直すため、すでに配信したデータを再び送ることがある
-   録画ファイルを外部アプリで直接開くためのプレイリストを提供する

### HLS配信

-   配信ごとにメモリー内の識別番号を割り当てる
-   プレイリストと分割された映像ファイルが利用できるまで準備中として扱う
-   利用可能な字幕がある場合はプレイリストへ字幕情報を追加する
-   利用者向け親プレイリストのパスを `./streamfiles/stream{streamId}.m3u8` とし、世代情報を追加しない
-   起動時にHLS保存先を確認し、残っているHLS成果物の識別番号を新しい配信へ割り当てない
-   配信停止中は識別番号を再利用せず、停止処理後にその識別番号だけに属するHLS成果物の削除を有限回試みる
-   開始または直前の継続要求から15秒以内に次の継続要求が届かない場合は自動停止する

HLSの識別番号と配信状態はメモリー内で管理する。新しい配信には、稼働中・停止中の配信とHLS成果物のいずれにも使用されていな
い0以上の識別番号を割り当てる。識別番号の候補が扱える最大値へ達した場合は0へ戻り、使用中の番号を飛ばして探し続ける。サー
バーは準備完了を待たずに受付結果と識別番号を返し、その後に準備状態を更新する。

停止時はHLS成果物の生成処理の終了確認と対象成果物の削除をそれぞれ有限回試み、その結果にかかわらず最終的に配信一覧から対
象を取り除いて識別番号を解放する。強制解放した番号を直後の新しい配信の第一候補にはせず、停止後に遅れて届いた結果から新し
い配信の状態を変更しない。終了未確認の処理または削除できない成果物が残った場合は、その内容を記録する。

### 配信状態と終了条件

-   配信中のライブ放送と録画済み番組を一覧表示する
-   配信形式、画質、HLSの準備状態、チャンネルまたは録画済み番組を表示する
-   指定した配信を停止する
-   管理操作によりすべての配信を停止する
-   直接接続へデータを送る配信は、視聴接続が閉じたときに停止する
-   ライブHLSは、停止要求、継続要求の途絶、視聴用変換の終了で停止し、変換を使用しない場合は放送受信の終了でも停止する
-   録画HLSは、停止要求または継続要求の途絶で停止し、配信用ファイルの生成終了だけでは停止しない
-   存在しない配信への停止要求は停止済みとして扱い、存在しない配信への継続要求は失敗とする
-   配信状態が変化したときに関係機能へ通知する

### 資源の停止

配信停止時は、配信形式に応じて放送受信、視聴用変換、録画ファイル読取、確認処理、HLS成果物の停止・解放を試みる。外部プロ
セスや放送受信など、終了通知を返す資源の停止には有限の待ち時間を適用する。HLSでは通常の停止確認後も終了しない処理へ強制
停止を要求し、停止確認と成果物削除が完了しなくても、サービスを継続できるよう対象を配信一覧から取り除き、識別番号を最終的
に解放する。

### Kodiへの再生依頼

-   設定されたKodiの送信先を名前で選ぶ
-   録画ファイルへアクセスするURLを要求の通信方式とホスト名から組み立てる
-   Kodiへ録画ファイルの再生開始を依頼する
-   送信先の利用者名とパスワードはKodiとの通信認証に使用する
-   認証情報を録画ファイルのURLへ埋め込まない
-   Kodiへの通信には有限の応答待ち時間を適用する

## 視聴の流れ

### ライブ放送

1. 利用者がチャンネル、配信形式、画質を選ぶ。
2. チューナーサーバーから放送データを取得する。
3. 形式に応じてそのまま配信するか、再生用変換を開始する。
4. 直接配信では視聴接続へデータを送り、HLSでは識別番号と準備状態を提供する。
5. 形式ごとの終了条件を検知したら関係資源の停止と解放を試みる。

### 録画済み番組

1. 利用者が録画ファイル、再生位置、配信形式、画質を選ぶ。
2. 録画済み番組と録画ファイルを確認する。
3. ファイルを指定位置から読み出し、そのまま、または視聴中だけ変換して配信する。
4. 録画中のファイルでは、末尾到達から1秒後に大きさが増えていれば追記分を配信する。大きさが変わっていなければ配信を終了
   し、読取位置より小さくなっていれば先頭から読み直す。
5. 接続終了またはHLSの終了条件を検知したら関係資源の停止と解放を試みる。

## 異常時と再起動時の動作

-   チャンネル、録画ファイル、録画済み番組、配信形式、画質を確認できない場合は配信を開始しない
-   放送データ、録画ファイル、視聴用変換の開始要求が配信受付前に失敗として返された場合は、開始済み資源の停止を試みて配信
    を失敗とする
-   一つの資源が終了した場合は、配信形式に定められた終了条件に従って対象配信の停止を試みる
-   Kodiの設定、録画ファイル、送信先との通信を確認できない場合は再生依頼を失敗とする
-   再起動前の配信、HLS識別番号、準備状態、継続期限を復元しない
-   サーバー全体の終了時に、すべての配信資源の解放完了まで待つ専用経路は提供しない

## 他の機能との関係

### 利用する機能

-   サーバー設定管理機能（`server-configuration`）: 配信形式、画質、変換方法、HLS保存先、およびKodiの接続先を提供する。
-   運用ログ記録機能（`server-operational-logging`）: 配信と視聴用変換の開始、終了、および失敗を記録する。
-   チューナーサーバー連携機能（`server-tuner-access`）: ライブ放送データの取得と停止を提供する。
-   録画済み番組管理機能（`server-recorded-content`）: 録画済み番組と録画ファイルを提供する。
-   メディア変換プロセス管理機能（`server-media-process-management`）: 視聴中の映像変換に使う実行枠を割り当てる。

### この機能を利用する機能

-   IPTV向けチャンネル一覧・番組表出力機能（`server-iptv-export`）: ライブ視聴先をチャンネル一覧へ掲載する。
-   Web・API・リアルタイム通知提供機能（`server-service-interface`）: 視聴操作、プレイリスト、映像データ、HLS継続、停
    止、およびKodi連携を公開する。

## この機能に含めないもの

-   番組を録画し、録画ファイルとして保存すること
-   録画済み番組と録画ファイルの登録情報を管理すること
-   後から利用する変換済みファイルを作成すること
-   メディア変換全体の優先順位と同時実行数を決めること
-   IPTV文書を生成すること
-   Web・APIの認証と認可を決めること
