# Web・API・リアルタイム通知提供機能

## この機能が提供するもの

EPGStation の Web 画面、各種 API、画像・映像ファイル、アップロード、リアルタイム更新通知を、ブラウザーや外部アプリへ提供
する機能である。

利用者から届いた要求を受け付け、番組情報、予約、録画、録画済み番組、エンコード、保存容量、映像配信、IPTV 向け出力などの
担当機能へ処理を依頼し、その結果を外部向けの形式で返す。各操作の業務判断は担当機能が行い、この機能は共通の窓口を担う。

## 主な機能

### Web 画面と静的ファイル

-   EPGStation の Web 画面を構成するファイルを配信する
-   画面で使用する画像とサムネイルを配信する
-   HLS のプレイリストと分割映像を配信する
-   配信サブディレクトリが設定されている場合は、その配下で Web 画面、API、API 文書、ファイル、リアルタイム通知を提供する
-   Web UI 向けの公開設定と EPGStation のバージョンを返す

公開設定には、リアルタイム通知のポート、録画保存先名、エンコード方法、再生用 URL 設定、ストリーミング方法、外部再生先
名、放送波の利用状態を含める。

### 機能別 API

-   チャンネル、番組表、番組検索、放送中番組、チャンネルロゴを提供する
-   予約、予約ルール、録画中番組の参照と操作を受け付ける
-   録画済み番組、タグ、保護状態、録画ファイル、ドロップログ、サムネイルの参照と操作を受け付ける
-   エンコードの追加、一覧、進捗確認、取消を受け付ける
-   録画保存先の容量を提供する
-   ライブ映像と録画済み映像の配信開始、継続、停止を受け付ける
-   IPTV 向けチャンネル一覧と電子番組表を提供する

API の入力・出力形式は機械可読な文書として提供し、説明画面を利用できる配布物がある場合は API 説明画面も提供する。

### 公開API契約

公開APIは、要求方法、要求先、入力名と必須性、成功状態、応答本文、応答ヘッダー、経路ごとのエラー状態と本文、ファイル形
式、リアルタイム通知名を維持する。実装用の型や文書上の誤りではなく、実際に受け付けて返している通信内容を互換性の基準とす
る。

特に次の動作を提供する。

-   録画済み映像のストリーム情報では、既存の綴りである `viodeFileId` を返す
-   予約一覧の `normal`、`conflicts`、`skips`、`overlaps` はそれぞれ配列として返す
-   ルール追加は `/rules` と `/rules/keyword` の両方で受け付ける
-   録画タイマーの再設定は本文なしの要求を受け付け、成功時に HTTP 200 と `{ code: 200 }` を返す
-   公開設定には `broadcast` を含める
-   リアルタイム通知では `updateStatus` と `updateEncode` を本文なしで送る

機械可読な API 文書は、予約一覧を配列として示し、ストリーム情報の既存フィールド名を実際の応答と一致させる。

### 共通の要求・応答処理

-   JSON、テキスト、ファイルアップロードなど、操作に応じた入力形式を受け付ける
-   API 定義に合わない要求を入力エラーとして返す
-   正常な JSON 応答には、利用者ごとのキャッシュへ保存しないためのヘッダーを付ける
-   プレイリスト、画像、ログ、映像などへ用途に応じた内容種類を付ける
-   映像ファイルの範囲要求へ部分応答を返す
-   ダウンロード指定では、ブラウザーが保存用として扱う応答を返す
-   各 HTTP 要求をアクセスログへ記録する

外部向け URL は、要求に含まれる Host と、実際の通信方式または転送された通信方式から組み立てる。サーバーエラーは既存のエ
ラー本文形式で返す。

### 動画ファイルのアップロード

-   一つの要求につき一件の動画ファイルと、録画済み番組、保存先、表示名、ファイル種類を受け付ける
-   受信中のファイルを一時保存し、受信完了後に録画済み番組管理機能へ渡す
-   アップロードの受信には有限な待ち時間を適用する
-   読み取り処理がエラーで完了した場合は一時ファイルの削除を試みる
-   受信待ち時間を超えた場合は受信を中止し、一時ファイルの削除を試みて入力エラーとして扱う
-   登録成功時は HTTP 200 と既存の成功本文を返す

### リアルタイム更新通知

-   HTTP または HTTPS の接続先でリアルタイム通知を提供する
-   設定されている場合は Web・API と別のポートでも提供する
-   状態変化通知を短時間まとめ、接続中の利用者へ本文なしの更新通知として送る
-   切断中の通知を保存または再送しない
-   再接続後の利用側は必要な情報を API から再取得する

### HTTP と HTTPS

-   設定に応じて HTTP、HTTPS、または両方を開始する
-   HTTPS では設定された秘密鍵と証明書を使用する
-   HTTPS の認証局証明書が設定されている場合は、接続元証明書を要求して検証する
-   API の全接続元許可が設定されている場合は Web と API の HTTP 応答で Cross-Origin Resource Sharing をすべての接続元へ
    許可する
-   リアルタイム通知はすべての接続元を許可する

Web、API、画像・映像、API 文書、リアルタイム通知へ一貫して適用する共通のアプリケーション認証は追加しない。

## 他の機能との関係

### 利用する機能

-   サーバー設定管理機能（`server-configuration`）: 接続先、配信サブディレクトリ、HTTP・HTTPS、公開用設定を提供する。
-   運用ログ記録機能（`server-operational-logging`）: HTTP アクセスと処理中の異常を記録する。
-   サーバー内部のプロセス間通信機能（`server-process-messaging`）: 管理側が担当する変更操作と結果を受け渡す。
-   番組情報・番組表機能（`server-program-guide`）: 番組表、番組検索、番組詳細、放送中番組、およびロゴを提供する。
-   録画予約管理機能（`server-reservation-management`）: 予約の参照、追加、変更、取消、および状態変更を提供する。
-   自動予約ルール機能（`server-reservation-rules`）: ルールの参照、追加、変更、削除、および候補検索を提供する。
-   予約録画実行機能（`server-recording-execution`）: 録画中の状態と録画操作を提供する。
-   録画済み番組管理機能（`server-recorded-content`）: 録画済み番組と関連情報の参照および変更操作を提供する。
-   録画済み番組のサムネイル管理機能（`server-thumbnail-management`）: サムネイルの参照と生成操作を提供する。
-   録画ファイル変換（エンコード）機能（`server-encoding`）: エンコードの参照、追加、変更、および取消を提供する。
-   録画保存先の容量管理機能（`server-storage-management`）: 録画保存先の容量情報を提供する。
-   映像配信・再生連携機能（`server-media-delivery`）: 放送中映像と録画ファイルの配信処理を提供する。
-   IPTV向けチャンネル一覧・番組表出力機能（`server-iptv-export`）: IPTV向けのチャンネル一覧と電子番組表を提供する。
-   状態変化通知・外部連携機能（`server-event-and-hook-delivery`）: 画面向けの更新通知を届ける。
-   機能間連携機能（`server-workflow-coordination`）: 利用者操作に伴う複数機能の後続処理を調整する。

### この機能を利用する機能

-   サーバー起動・稼働管理機能（`server-application-runtime`）: この機能を起動し、停止時には再起動を試みる。

## この機能に含めないもの

-   予約、録画、検索、削除、変換、配信の業務判断
-   番組情報や録画済み番組のデータベース保存
-   チューナーサーバーからの番組情報や映像の取得
-   業務上どの状態変化を画面通知の契機にするかの決定
-   Web 画面内の表示内容、画面遷移、操作方法
-   サーバー全体の起動と再起動の管理
