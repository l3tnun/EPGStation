# 自動予約ルール機能

## この機能が提供するもの

利用者が保存した条件から録画予約の候補を作り、条件や番組情報の変化に合わせて候補を更新する機能である。

番組名などの条件で番組を探すルールと、決まった曜日・時刻の放送枠を指定するルールを扱う。候補には録画条件を引き継ぐが、予
約の保存、除外、重複、競合は録画予約管理が行う。

## 主な機能

### ルールの管理

-   ルールを追加、変更、削除、有効化、無効化する
-   ルールの一覧、詳細、件数を取得する
-   条件による一覧の絞り込みとページ分割を行う
-   保存されたすべてのルールのキーワード候補を、ルール識別番号順に一ルール一件取得する。曜日・時刻指定ルールも含み、同じ
    キーワードを持つ複数ルールも別々に返す

### 番組検索ルール

-   包含キーワードと除外キーワードを指定する
-   番組名、説明、詳細情報のどこを検索するか指定する
-   大文字・小文字の扱いと正規表現の利用を指定する
-   放送局、放送波、ジャンル、曜日・時間帯、無料番組、番組長、検索期間を組み合わせる
-   番組情報を検索し、現在放送中または将来放送される候補を作る

検索方法の一部は利用するデータベースによって動作が異なる。検索条件を受け付ける公開形式は維持し、具体的な検索式はデータ
ベース保存・検索機能が提供する。

### 曜日・時刻指定ルール

-   放送局、曜日、開始時刻、録画時間を指定する
-   ルール名として使うキーワードと放送局一覧は必須とする
-   時間指定が0件の場合や曜日を一つも選んでいない時間指定は保存できるが、そこから予約候補は作られない
-   サーバー実行環境のローカル年月日を取り出し、その年月日の日本標準時0時を候補日の基準とする。指定曜日との照合にはサー
    バー実行環境のローカル曜日を使用する
-   当日を含む8日分の放送枠を候補として展開する
-   番組情報がない時間帯でも、指定した開始時刻と録画時間から候補を作る

### 録画条件の継承

-   途中終了の許可、タグ、保存先、ファイル名形式を候補へ引き継ぐ
-   録画後のエンコード方法、出力先、元ファイル削除の有無を候補へ引き継ぐ
-   検索条件、重複回避条件、およびエンコード方法の組み合わせを検査し、成立しないルールを拒否する

### 録画履歴との重複照合

-   番組検索ルールで録画済み番組との重複回避を指定できる
-   指定された期間の録画履歴を候補番組と照合する
-   重複候補であることを録画予約管理へ伝える
-   利用者による重複解除と最終的な重複状態は録画予約管理へ委ねる

### 候補の再計算

-   ルールの追加、変更、有効化、無効化を契機に対象ルールを再計算する
-   番組情報の更新後に有効なルールを再計算する
-   ルールの現在の候補と保存済み予約の差分を録画予約管理へ渡す
-   一件のルール処理に失敗しても、処理できる他のルールを続ける

## 利用の流れ

1. 利用者がルール条件と録画条件を入力する。
2. 条件、保存先、エンコード方法を確認してルールを保存する。
3. 番組を検索するか、曜日・時刻から候補を展開する。
4. 必要に応じて録画履歴と照合する。
5. 候補と録画条件を録画予約管理へ渡す。
6. 録画予約管理が予約の追加、更新、削除、競合、除外、重複を決定する。

## 異常時の動作

-   必須条件、検索条件、重複回避条件、またはエンコード方法が成立しないルールは保存しない。曜日・時刻指定ルールではキー
    ワードと放送局一覧も必須とする
-   番組検索または録画履歴の取得に失敗した場合は、そのルールの候補更新を失敗として扱う
-   一件のルール更新に失敗しても、処理できる他のルール更新を続ける
-   サーバー起動後は保存済みの有効なルールを読み直し、現在の番組情報から候補を再計算する

## 他の機能との関係

### 利用する機能

-   サーバー設定管理機能（`server-configuration`）: ルールで指定できる録画条件、保存先、およびエンコード方法を提供する。
-   運用ログ記録機能（`server-operational-logging`）: ルール変更、候補計算、および異常を記録する。
-   番組情報・番組表機能（`server-program-guide`）: 条件に一致する番組を検索するための番組情報を提供する。
-   録画済み番組管理機能（`server-recorded-content`）: 重複照合に用いる録画履歴と、削除したルールに関連する録画済み番組
    を提供する。
-   データベース保存・検索機能（`server-persistence`）: ルールを保存・検索し、番組検索に必要なデータ操作を提供する。

### この機能を利用する機能

-   状態変化通知・外部連携機能（`server-event-and-hook-delivery`）: ルールの状態変化を通知に利用する。
-   バックアップ・復元・旧版移行機能（`server-management-tools`）: ルール情報をバックアップ、復元、および旧版移行の対象
    として扱う。
-   サーバー内部のプロセス間通信機能（`server-process-messaging`）: 受け付けたルール操作を依頼する。
-   録画予約管理機能（`server-reservation-management`）: 条件に一致した番組と時間帯の予約候補を取得する。
-   Web・API・リアルタイム通知提供機能（`server-service-interface`）: ルールの一覧と詳細を取得し、作成、変更、有効化、無
    効化、および削除を依頼する。
-   機能間連携機能（`server-workflow-coordination`）: 番組やルールの変化に応じて候補の再計算を依頼する。

## この機能に含めないもの

-   番組情報の取得・更新
-   予約の保存とチューナー競合判定
-   手動予約と番組リレー予約の作成
-   録画の開始、取消、録画ファイル作成
-   録画履歴と録画済みファイルの削除
