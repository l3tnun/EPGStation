# 機能間連携機能

## この機能が提供するもの

番組情報、予約、自動予約ルール、録画、録画済み番組、サムネイル、エンコードのいずれかで状態が変わったとき、または利用者の
一つの操作が複数機能にまたがるとき、必要な後続処理を選び、実行する順序を調整する機能である。

例えば、番組情報の更新後に予約を再計算する、録画完了後にサムネイル作成とエンコードを依頼するといった処理をつなぐ。各機能
が自分の状態を所有したまま、EPGStation全体に必要な後続処理を開始できるようにする。

状態変化を受けるたびに必要な処理を直接依頼し、各依頼の完了と失敗は依頼先の機能が管理する。

## 主な機能

### 番組情報更新後の連携

-   番組情報の更新完了を受け取る
-   古い録画履歴の整理を依頼する
-   手動予約と番組リレー予約を更新する
-   有効な自動予約ルールを再評価する
-   最初の番組情報更新か、それ以降の更新かを予約更新へ伝える

録画履歴の整理に失敗しても、予約更新とルール再評価は続ける。

### 自動予約ルール変更後の連携

-   ルールの追加、変更、有効化、無効化を受けて、そのルールの予約を再計算する
-   ルールの削除を受けて、関連する将来予約を再計算する
-   削除したルールと録画済み番組の関連付けを解除する
-   ルール変更を接続中の画面へ知らせる

ルール削除後の予約再計算と関連付け解除は別々に進むため、一方だけ成功することがある。

### 予約変更後の連携

-   追加された予約を録画待ちへ登録する
-   変更された予約を録画待ち、録画準備、録画中の状態へ反映する
-   削除された予約に対応する録画待ち、録画準備、録画中処理を取り消す
-   予約の追加、変更、削除を画面と設定済み外部コマンドへ知らせる

### 録画準備・失敗・開始後の連携

-   録画準備の開始、取消、失敗を画面と設定済み外部コマンドへ知らせる
-   録画準備または録画の再試行上限到達を受けて、対象予約の取消を依頼する
-   録画開始時に、予約で指定されたタグを録画済み番組へ一件ずつ関連付ける
-   録画開始を画面と設定済み外部コマンドへ知らせる
-   録画失敗を画面へ知らせ、録画済み番組が作成されている場合は設定済み外部コマンドへも知らせる

タグの解釈または関連付けに失敗した場合は失敗を記録し、残りのタグと通知を続ける。

### 録画完了後の連携

-   手動予約または番組リレー予約を必要に応じて取り消す
-   自動予約の録画完了後は、重複判定を反映するため対象ルールの予約を再計算する
-   録画ファイルがある場合はサムネイル作成を依頼する
-   予約に指定された最大3件のエンコードを順に依頼する
-   予約で指定されたタグを録画済み番組へ一件ずつ関連付ける
-   タグ処理後に、録画完了を画面と設定済み外部コマンドへ知らせる

予約整理、サムネイル作成、エンコードは、各依頼先での業務完了を待たずに次の依頼へ進む。これらが進行中でもタグ付けと完了通
知を開始する。同期的な依頼失敗によっては、それより後の処理へ到達しないことがある。すでに開始した処理は自動的に取り消さな
い。

### 番組リレーと録画済み番組変更

-   番組リレー候補を順番に処理し、リレー元の予約設定を引き継いだ予約追加を依頼する
-   一件のリレー予約に失敗しても、残りの候補を続ける
-   アップロードされた録画ファイルにサムネイルが必要な場合は作成を依頼する
-   録画中の録画済み番組が削除された場合は、対応する予約の取消を依頼する
-   録画済み番組、録画ファイル、保護状態、タグ、サムネイルの変更を画面へ知らせる
-   エンコード完了時に、設定済み外部コマンドの実行を依頼する

### 利用者による録画済み番組の削除

1. 対象に対する待機中・実行中のエンコードを停止する。
2. 録画済み番組の存在と保護状態を確認する。
3. 対象が録画中で、対応する予約と録画処理を確認できる場合は録画を停止する。
4. サムネイル、録画ファイル、ドロップログ、録画済み番組の削除を依頼する。

エンコード停止は保護状態の確認より先に行う。このため、保護中または存在しない対象で削除が失敗しても、停止したエンコードは
自動再開しない。録画停止後に削除が失敗した場合も、停止した録画を自動再開しない。各ファイルまたは関連情報の削除失敗は記録
するが、残りの削除を続けることがある。

## 後続処理の完了と再実行

-   状態変化を受け付けたことと、後続処理の業務完了を分けて扱う
-   画面通知は最新状態を再取得するきっかけであり、後続処理全体の成功を示さない
-   外部コマンドの受付または終了も、後続処理全体の成功を示さない
-   一つの後続処理が失敗しても、別の処理を続ける場合がある
-   共通の連携完了状態と、処理ごとの共通結果一覧は持たない
-   同じ状態変化を再び受け取ると、後続処理も再び依頼することがある
-   再起動時に途中だった連携を保存済み段階から自動再開する保証はない

## 他の機能との関係

### 利用する機能

-   運用ログ記録機能（`server-operational-logging`）: 後続処理の依頼、完了、および失敗を記録する。
-   番組情報・番組表機能（`server-program-guide`）: 番組情報の更新完了を伝え、後続処理に必要な番組情報を提供する。
-   録画予約管理機能（`server-reservation-management`）: 予約の再計算、追加、変更、および取消を行う。
-   自動予約ルール機能（`server-reservation-rules`）: 変更されたルールと再計算する予約候補を提供する。
-   予約録画実行機能（`server-recording-execution`）: 録画準備、開始、失敗、完了、および番組リレー候補を伝える。
-   録画済み番組管理機能（`server-recorded-content`）: 録画履歴、録画済み番組、録画ファイル、およびタグの操作を提供す
    る。
-   録画済み番組のサムネイル管理機能（`server-thumbnail-management`）: 録画完了後のサムネイル生成を受け付ける。
-   録画ファイル変換（エンコード）機能（`server-encoding`）: エンコードの開始、取消、および完了結果を提供する。
-   状態変化通知・外部連携機能（`server-event-and-hook-delivery`）: 状態変化を画面へ通知し、設定された外部コマンドを実行
    する。

### この機能を利用する機能

-   サーバー起動・稼働管理機能（`server-application-runtime`）: 起動時に機能間の連携処理を開始する。
-   Web・API・リアルタイム通知提供機能（`server-service-interface`）: 利用者による録画済み番組削除など、複数機能にまたが
    る操作を依頼する。

## この機能に含めないもの

-   各機能が所有する業務状態と判断方法
-   予約競合の計算、録画、画像生成、エンコード、ファイル削除そのもの
-   サーバー内通知、画面通知、外部コマンドを実際に届ける方法
-   Web APIの受付、応答、認証
-   録画保存先の容量不足による自動削除
-   後続処理の共通の重複排除と自動再試行
