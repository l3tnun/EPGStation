# サーバー設定管理機能

## この機能が提供するもの

EPGStation Server の動作に必要な設定を YAML 形式の設定ファイルから読み込み、省略値と表記を整えて各機能へ提供する機能であ
る。

Web UI・API の公開方法、チューナーサーバーとデータベース、録画保存先、予約と録画、番組情報更新、サムネイル、エンコード、
ストリーミング、外部コマンドなどの設定を扱う。設定ファイルが変更された場合は再読み込みを試み、成功した後の取得要求へ新し
い内容を渡す。

## 主な機能

### 設定の読み込みと補完

-   YAML 形式の設定ファイルを読み込む
-   省略された主要項目へ標準値を補う
-   ストリーミング設定の一部が省略されている場合は、基準となる設定から選択肢を補う
-   サーバー内の基準位置を表す記号を実際の位置へ置き換える
-   URL のサブディレクトリと保存先の表記を整える
-   一時録画用の保存先を通常の録画保存先一覧から除外する

### 起動に必要な設定の確認

HTTP または HTTPS のどちらかで Web UI・API を公開できる最低条件を確認する。設定ファイルが存在しない、読み取れない、YAML
として解釈できない、またはこの最低条件を満たさない場合は、後続機能を開始しない。

この機能は設定全体へ一律の型・範囲・組合せ検査を行うものではない。次の「処理量と処理期限の設定」の6項目を除き、各設定を
利用するときに必要となる追加条件は、その設定を使用する機能が扱う。

### 処理量と処理期限の設定

エンコード待機上限、同時アップロード数、アップロード受信期限、サムネイル待機上限、外部コマンド待機上限、外部コマンド期限
の6項目へ既定値を補い、許容範囲を検証する。不正な値は設定エラーとし、これらを利用する機能は起動時に一度だけ値を保持す
る。公開用設定には含めない。

### 設定の提供

-   一回の取得では、その時点の設定を独立した一まとまりとして渡す
-   取得側が内容を変更しても、他の取得結果や管理中の設定へ影響しないようにする
-   設定を保持済みの機能へ、再読み込み後の内容を自動配信しない

役割の異なるサーバー処理は、それぞれ設定を読み込み、保持する。このため、別々の処理が同じ時点で必ず同じ再読み込み結果を使
うとは限らない。

### 設定変更の再読み込み

1. 設定ファイルの変更を検知する。
2. 変更後の YAML を読み込み、起動時と同じ補完と表記整理を行う。
3. 成功した場合だけ、その処理が提供する設定を新しい内容へ切り替える。
4. 失敗した場合は切り替えず、直前まで利用していた設定を維持して異常を記録する。

再読み込みの完了を各機能へ通知したり、実行中の処理を停止・再起動したりすることは、この機能の役割ではない。

### Web UI へ公開する設定

Web UI が利用する次の情報だけを公開用に整える。

-   リアルタイム通知の接続先ポート
-   録画保存先名とエンコード方法名
-   利用可能なストリーミング方法
-   端末別の再生用 URL 設定
-   外部再生先の名前

データベースの認証情報、内部の保存場所、外部コマンドなど、サーバー内部でのみ使う設定は公開用設定へ含めない。放送波の利用
状態など、設定ファイルに由来しない情報との組合せは Web・API・リアルタイム通知提供機能が行う。

### 外部コマンド設定の解釈

外部コマンドは、空白で実行ファイルと引数へ分ける現在の設定形式を使用する。実行ファイルを Node.js 実行ファイルへ置き換え
る記号、サーバーの基準位置を表す記号、引数中の空白を表す記号を解釈し、実行ファイルが存在しない場合はコマンドを開始しな
い。

## 他の機能との関係

### 利用する機能

-   運用ログ記録機能（`server-operational-logging`）: 読み込み、再読み込み、および異常を記録する。

### この機能を利用する機能

-   サーバー起動・稼働管理機能（`server-application-runtime`）: 起動時に設定を取得して各機能を準備する。
-   録画ファイル変換（エンコード）機能（`server-encoding`）: 変換方法、実行数、および保存先を取得する。
-   状態変化通知・外部連携機能（`server-event-and-hook-delivery`）: 解釈済み外部コマンドと実行時間制限を取得する。
-   IPTV向けチャンネル一覧・番組表出力機能（`server-iptv-export`）: チャンネル順と公開先を取得する。
-   バックアップ・復元・旧版移行機能（`server-management-tools`）: 管理情報の接続先と保存先を取得する。
-   映像配信・再生連携機能（`server-media-delivery`）: 配信形式、変換方法、および接続先を取得する。
-   メディア変換プロセス管理機能（`server-media-process-management`）: 共有実行数を取得する。
-   データベース保存・検索機能（`server-persistence`）: データベース方式と接続情報を取得する。
-   番組情報・番組表機能（`server-program-guide`）: 更新間隔と対象条件を取得する。
-   録画済み番組管理機能（`server-recorded-content`）: 保存先と履歴条件を取得する。
-   予約録画実行機能（`server-recording-execution`）: 録画時刻、保存先、および再試行条件を取得する。
-   録画予約管理機能（`server-reservation-management`）: 予約条件と保存先を取得する。
-   自動予約ルール機能（`server-reservation-rules`）: ルールで利用できる録画条件を取得する。
-   Web・API・リアルタイム通知提供機能（`server-service-interface`）: 接続先、通信方式、および公開用設定を取得する。
-   録画保存先の容量管理機能（`server-storage-management`）: 保存先、監視間隔、および容量条件を取得する。
-   録画済み番組のサムネイル管理機能（`server-thumbnail-management`）: 保存先と生成条件を取得する。
-   チューナーサーバー連携機能（`server-tuner-access`）: 接続先、優先度、および応答時間を取得する。

## この機能に含めないもの

-   各設定を使った予約、録画、削除、配信などの業務判断
-   ブラウザー内に保存する画面設定
-   運用ログの出力先と保持方法
-   設定変更後に各機能を停止または再起動すること
-   サーバー全体の起動順序と終了順序
