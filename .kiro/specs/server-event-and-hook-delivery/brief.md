# 状態変化通知・外部連携機能

## この機能が提供するもの

予約、録画、録画済み番組、サムネイル、エンコードなどの状態変化を、関係するサーバー機能、接続中の画面、設定された外部コマ
ンドへ届ける機能である。

この機能は、状態変化に応じて行う業務処理を決めない。機能間連携が選んだ通知先へ変化を伝え、画面には最新状態を再取得する
きっかけを送り、外部コマンドには状態変化ごとの情報を渡す。

## 主な機能

### サーバー内の通知

-   番組情報、ルール、予約、録画、録画済み番組、タグ、サムネイル、エンコードの状態変化を受け付ける
-   一つの状態変化を必要とする複数の処理へ届ける
-   通知先が開始した処理の完了を、状態変化の発生元が待つ共通の仕組みは持たない
-   同じ状態変化を繰り返し受け取った場合も、共通の重複排除は行わない

### 別々に動くサーバー機能間の通知

-   予約や録画などを管理する処理から、Web UI・APIを提供する処理へ状態変化を伝える
-   エンコードの受付、取消、進捗、完了、失敗などを必要な処理へ中継する
-   通信が切れている間の通知を保存し、再接続後に必ず再送することは保証しない

### 接続中の画面への通知

-   予約、録画、録画済み番組、タグ、サムネイル、エンコードなどの変化を画面向け通知としてWeb・API・リアルタイム通知提供機
    能へ渡す
-   通知の集約時間と接続中の画面への送信はWeb・API・リアルタイム通知提供機能へ委ねる
-   通知には状態全体を含めず、画面が必要な情報を再取得するきっかけとして扱う
-   切断中の通知は再送されないことがあるため、再接続した画面は現在状態を再取得して差を埋める

### 外部コマンドの実行

設定されている場合、次の状態変化に応じた外部コマンドを実行する。

-   予約の追加、変更、削除
-   録画準備の開始、取消または失敗
-   録画の開始、失敗、完了
-   エンコードの完了

外部コマンドには、状態変化の種類に応じて、予約、番組、放送局、録画済み番組、録画ファイル、ドロップ集計、エンコード結果な
どの情報を環境変数として渡す。設定されていない種類のコマンドは実行しない。

外部コマンドは種類をまたいだ一つの待ち行列へ受付順に追加し、一件ずつ実行する。待機件数には設定可能な有限上限を設け、設定
がない場合は64件とする。上限へ達した場合は新しいコマンドを追加も実行もせず、過負荷を記録し、受付済みコマンドの順序と実行
を変更しない。自動再試行は行わず、同じ状態変化を再び受け取った場合も重複したコマンド実行を共通に抑止しない。

待機上限には1以上10,000以下の整数だけを使用でき、条件を満たさない設定では外部コマンド実行機能を開始しない。上限は機能の
起動時に読み取り、稼働中の設定変更は再起動後に反映する。

外部コマンド実行時間制限の設定値を各コマンドへ適用し、設定がない場合は300秒とする。時間制限へ達した実行は終了を要求し、
その実行を完了扱いにはしない。

### 外部コマンドへ渡す環境

-   コマンド探索に必要な情報と、状態変化ごとに定めた情報を渡す
-   サーバーの実行環境全体は引き継がない
-   値が存在しない項目は、項目ごとの定めに従い、文字列の `null`、空文字、または未設定となる
-   サーバー設定管理機能が解釈した実行対象と引数を使用し、コマンド文字列を独自に再解釈しない

## 通知の流れ

1. 状態を所有する機能が、保存の完了や処理結果を状態変化として知らせる。
2. 機能間連携が、必要な後続処理、画面通知、外部コマンドの種類を決める。
3. この機能が、サーバー内、別々に動く処理、画面、外部コマンドのうち選ばれた経路へ通知する。
4. 画面向け通知の集約と送信をWeb・API・リアルタイム通知提供機能へ委ねる。
5. 外部コマンドは一つの待ち行列で順に実行する。

状態変化の受付、通知先への受け渡し、画面への送信、外部コマンドの終了は、それぞれ別の出来事である。いずれかの通知に失敗し
ても、元の予約、録画、エンコードなどの確定済み状態は取り消さない。

## 異常時の動作

-   サーバー内の通知先が失敗を返した場合は、その失敗を記録する
-   別々に動く処理または画面へ接続できない場合、その通知は失われることがある
-   外部コマンドを起動できない場合または異常終了した場合は失敗を記録し、次の待機中コマンドへ進む
-   外部コマンドが実行時間制限へ達した場合は終了を要求し、自動再試行しない
-   外部コマンド用の予約、放送局、録画済み番組などを取得できない場合は、そのコマンドを実行できないことがある

## 他の機能との関係

### 利用する機能

-   サーバー設定管理機能（`server-configuration`）: 解釈済み外部コマンド、待機上限、および実行時間制限を提供する。
-   運用ログ記録機能（`server-operational-logging`）: 通知と外部コマンドの開始、終了、および失敗を記録する。
-   サーバー内部のプロセス間通信機能（`server-process-messaging`）: 別々に動くサーバー機能間の通信経路を提供する。
-   番組情報・番組表機能（`server-program-guide`）: 番組情報の状態変化を提供する。
-   自動予約ルール機能（`server-reservation-rules`）: ルールの状態変化を提供する。
-   録画予約管理機能（`server-reservation-management`）: 予約の状態変化を提供する。
-   予約録画実行機能（`server-recording-execution`）: 録画の状態変化を提供する。
-   録画済み番組管理機能（`server-recorded-content`）: 録画済み番組、録画ファイル、およびタグの状態変化を提供する。
-   録画済み番組のサムネイル管理機能（`server-thumbnail-management`）: サムネイルの状態変化を提供する。
-   録画ファイル変換（エンコード）機能（`server-encoding`）: エンコードの状態変化を提供する。

### この機能を利用する機能

-   Web・API・リアルタイム通知提供機能（`server-service-interface`）: 画面向け通知を受け取り、集約して送信する。
-   機能間連携機能（`server-workflow-coordination`）: 選択した画面通知と外部コマンドの配送を依頼する。

## この機能に含めないもの

-   通知元となる業務状態の変更
-   状態変化に応じて実行する業務処理の選択
-   Web UIやAPIの接続受付と認証
-   外部コマンドが行う処理の内容
-   通知失敗を理由とする業務状態の巻き戻し
-   通知の永続保存、共通の重複排除、自動再試行
