# データベース保存・検索機能

## この機能が提供するもの

EPGStation Server が扱う番組、予約、録画済み番組などの情報をデータベースへ保存し、サーバーを再起動した後も利用できるよう
にする機能である。

SQLite または MySQL へ接続し、各機能へ追加、更新、削除、検索、件数取得を提供する。データ構造の更新が必要な場合は接続時に
適用する。

## 主な機能

### データベース接続

-   設定された SQLite または MySQL へ接続する
-   SQLite の外部拡張が設定されている場合は、最初の接続時に指定順で読み込む
-   SQLite の外部拡張を読み込めない場合は、その最初のデータベース利用要求をエラーにする
-   最初の利用時に接続を作り、後続の処理で同じ接続を利用する
-   簡単な問い合わせを実行し、データベースが応答できるか確認する
-   接続を作る一回の試行はデータベースドライバーの結果を待ち、EPGStation独自の時間制限を追加しない
-   終了処理から要求された場合に接続を閉じる

### 保存する情報

-   放送局と番組情報
-   予約と自動予約ルール
-   録画済み番組と録画履歴
-   録画ファイル、ドロップログ、サムネイル
-   録画済み番組のタグと関連付け

各情報がどのような状態を持ち、いつ変更できるかは、それぞれを管理する機能が決定する。

### 情報の追加・更新・検索

-   1 件の追加、更新、削除を行う
-   条件に一致する 1 件または複数件を検索する
-   一覧の並び替え、絞り込み、ページ分割、件数取得に必要なデータ操作を行う
-   関連する録画済み番組、録画ファイル、サムネイル、タグなどをまとめて取得する
-   SQLite と MySQL の違いに合わせて、真偽値や文字検索条件を調整する
-   SQLite では、正規表現を利用可能とする設定に従って正規表現検索の可否を決める
-   保存値を対象情報の形式として復元できない場合は、空値や既定値へ読み替えず読取エラーにする

SQLite と MySQL では、大文字と小文字の区別や正規表現検索を利用できる条件が異なる。この機能は、それぞれのデータベースに定
められた検索方法を使用し、両方式の検索結果が常に同じになるとは扱わない。

### 変更をまとめて確定する処理

複数予約の一括変更、番組情報の全件または指定放送局単位の置換、およびバックアップ復元の種類ごとの入替えでは、その処理また
は段階のデータベース変更がすべて成功した場合に確定する。途中で失敗した場合は、その処理または段階の変更を取り消す。

このまとまりは処理ごとに異なる。バックアップ復元全体を一つの変更として扱うものではなく、番組情報の増分更新を含むその他の
複数件処理では一部の変更が残る場合がある。番組情報の増分更新では、個別の削除・追加・更新失敗を記録した後も残りを続けて確
定する場合がある。

### データ操作の再試行

共通再試行を利用する読み書きと検索でエラーが起きた場合は1秒待ち、次の試行が残っていれば再試行する。最初の実行を含めて最
大5回試し、すべて失敗した場合は最後のエラーを依頼元へ返す。

処理単位で変更をまとめる操作はこの共通再試行の対象にせず、その処理または段階の変更を取り消してエラーを返す。

### データ構造の更新

接続時に、利用するデータベース方式に対応する未適用のデータ構造更新を順番に実行する。更新に失敗した場合はデータベースを利
用可能として扱わず、後の接続確認で接続作成と未適用更新を再び試みる。適用済み更新を接続時に自動降格する機能は持たない。

## 起動時の流れ

1. サーバー設定からデータベース方式と接続情報を取得する。
2. 対応するデータベースへ接続する。
3. SQLite の外部拡張が設定されている場合は読み込む。
4. 未適用のデータ構造更新を実行する。
5. 簡単な問い合わせに成功したことを確認する。
6. 各機能からの保存と検索を受け付ける。

サーバー起動時にデータベースへ接続できない場合、サーバー起動・稼働管理機能は確認処理が失敗を返した後に1秒待って接続確認
を続ける。接続時は利用するデータベースドライバーの結果を待ち、一回の接続試行にも依存先の復旧待ち全体にもEPGStation独自の
時間制限を追加しない。

## 他の機能との関係

### 利用する機能

-   サーバー設定管理機能（`server-configuration`）: データベース方式と接続情報を提供する。
-   運用ログ記録機能（`server-operational-logging`）: 接続、データ構造更新、保存、および検索の異常を記録する。

### この機能を利用する機能

-   サーバー起動・稼働管理機能（`server-application-runtime`）: データベースへ接続できるまで待機する。
-   IPTV向けチャンネル一覧・番組表出力機能（`server-iptv-export`）: 保存された放送局と番組を読み取る。
-   バックアップ・復元・旧版移行機能（`server-management-tools`）: 管理情報の読み出し、置き換え、および追加を依頼する。
-   番組情報・番組表機能（`server-program-guide`）: 放送局と番組の保存および検索を依頼する。
-   録画済み番組管理機能（`server-recorded-content`）: 録画済み番組と関連情報の保存および検索を依頼する。
-   録画予約管理機能（`server-reservation-management`）: 予約の保存と検索を依頼する。
-   自動予約ルール機能（`server-reservation-rules`）: ルールと検索条件の保存および検索を依頼する。
-   録画保存先の容量管理機能（`server-storage-management`）: 自動削除候補の検索を依頼する。
-   録画済み番組のサムネイル管理機能（`server-thumbnail-management`）: サムネイルと録画済み番組の関係を保存する。

## この機能に含めないもの

-   予約、録画、録画済み番組、ルールなどの状態と変更可否の判断
-   録画映像、サムネイル画像、ドロップログなどの実ファイル管理
-   バックアップ、復元、旧版移行の操作手順
-   API 応答への変換
-   データベース自体のインストール、監視、バックアップ、障害復旧
-   SQLite と MySQL 以外のデータベース
