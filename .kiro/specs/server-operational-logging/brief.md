# 運用ログ記録機能

## この機能が提供するもの

EPGStation Server の動作状況、利用状況、警告、エラーを運用者が確認できる形で記録する機能である。

サーバー内部の処理、Web・API へのアクセス、映像配信、エンコードを用途別に記録する。各機能は記録したい用途と重要度を指定
し、この機能が設定に従って画面またはログファイルへ出力する。

## 主な機能

### 起動時のログ準備

-   詳細なログ設定を利用する前は、画面へログを出力する
-   サーバー内で役割の異なる処理ごとにログ設定を読み込む
-   設定された出力先、重要度、ファイル切替条件を適用する
-   ログ設定を読み込めない場合は、該当する処理を開始しない

### 用途別の記録

-   システムログ: 起動、設定、データベース、予約、録画などの動作と異常を記録する
-   アクセスログ: Web UI、API、ファイル取得などの HTTP アクセスを記録する
-   ストリームログ: ライブ視聴と録画済み番組の配信状況や異常を記録する
-   エンコードログ: エンコードの開始、進行、終了、異常を記録する

記録では、詳細、通常情報、警告、エラー、重大な異常などの重要度を使い分ける。何を記録へ渡すかは各機能が決め、この機能は渡
された内容を指定された用途へ出力する。

### 処理の役割ごとの出力

予約・録画を管理する処理、Web UI・API を提供する処理、番組情報を更新する処理は、それぞれのログ設定を使う。ログファイルを
使う設定では、指定された容量に達したファイルを切り替え、設定された数の過去ファイルを保持する。

ログ設定は各処理の起動時に読み込む。稼働中にログ設定を変更しても自動では反映せず、反映には該当する処理の再起動が必要であ
る。

### 重大な異常の記録

-   捕捉されなかった例外を重大な異常として記録する
-   処理結果を待たれないまま失敗した非同期処理を重大な異常として記録する
-   他機能が検知した処理停止や再起動を記録する

異常を記録した後に処理を継続、停止、または再起動する判断は、この機能では行わない。

## 処理の流れ

1. 起動直後は画面出力を使って準備状況を記録する。
2. 処理の役割に対応するログ設定を読み込む。
3. システム、アクセス、ストリーム、エンコードの記録先を準備する。
4. 各機能から渡された記録を、用途と重要度に応じた出力先へ送る。

## 他の機能との関係

### 利用する機能

-   なし

### この機能を利用する機能

-   サーバー起動・稼働管理機能（`server-application-runtime`）: 起動、終了、および再起動の状況と異常を記録する。
-   サーバー設定管理機能（`server-configuration`）: 設定の読み込みと再読み込みの結果を記録する。
-   録画ファイル変換（エンコード）機能（`server-encoding`）: エンコードの開始、進捗、完了、および失敗を記録する。
-   状態変化通知・外部連携機能（`server-event-and-hook-delivery`）: 通知と外部コマンドの実行状況や失敗を記録する。
-   IPTV向けチャンネル一覧・番組表出力機能（`server-iptv-export`）: チャンネル一覧と番組表の生成状況や失敗を記録する。
-   バックアップ・復元・旧版移行機能（`server-management-tools`）: バックアップ、復元、および移行の状況や失敗を記録す
    る。
-   映像配信・再生連携機能（`server-media-delivery`）: 映像配信と再生用変換の状況や失敗を記録する。
-   メディア変換プロセス管理機能（`server-media-process-management`）: 変換プロセスの開始、入れ替え、終了、および異常を
    記録する。
-   データベース保存・検索機能（`server-persistence`）: 接続、保存、検索、およびデータ構造更新の状況や失敗を記録する。
-   サーバー内部のプロセス間通信機能（`server-process-messaging`）: 送信不能、応答待ち、および通知処理の異常を記録する。
-   番組情報・番組表機能（`server-program-guide`）: 放送局と番組の取得、更新、および検索の状況や失敗を記録する。
-   録画済み番組管理機能（`server-recorded-content`）: 録画済み番組と関連ファイルの操作状況や失敗を記録する。
-   予約録画実行機能（`server-recording-execution`）: 録画準備、録画開始、録画終了、および失敗を記録する。
-   録画予約管理機能（`server-reservation-management`）: 予約の追加、更新、取消、および競合計算の状況や失敗を記録する。
-   自動予約ルール機能（`server-reservation-rules`）: ルールの変更、評価、および候補更新の状況や失敗を記録する。
-   Web・API・リアルタイム通知提供機能（`server-service-interface`）: HTTPアクセス、API処理、およびリアルタイム通知の状
    況や異常を記録する。
-   録画保存先の容量管理機能（`server-storage-management`）: 容量確認と自動削除の状況や失敗を記録する。
-   録画済み番組のサムネイル管理機能（`server-thumbnail-management`）: サムネイルの生成と整理の状況や失敗を記録する。
-   チューナーサーバー連携機能（`server-tuner-access`）: チューナーサーバーとの通信状況や失敗を記録する。
-   機能間連携機能（`server-workflow-coordination`）: 状態変化に応じた後続処理の依頼と失敗を記録する。

## この機能に含めないもの

-   予約、録画、配信、エンコードなどの業務判断
-   異常発生後の再試行、停止、再起動の判断
-   メトリクス、分散トレース、利用分析、監査証跡の収集
-   ブラウザー側のエラー収集
-   ログファイルを録画ファイルや配信ファイルとして管理すること
